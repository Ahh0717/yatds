# 哈夫曼树的构造与编码（huffman）

> 哈夫曼树是带权路径长度（WPL）最短的二叉树，也称最优二叉树。
> 频率高的字符用短编码、频率低的字符用长编码，从而压缩数据。

对应题面：`src/Tree/Baseline/huffman/README.md`。

## 2. 数据结构

全部定义在 `code/huffman-tree.h`，`namespace dsaac`（与题面一致）。

```cpp
template <typename T, std::size_t N = 2>
struct Node {
    T data;
    std::array<std::unique_ptr<Node>, N> children;

    Node(const T &value);
    Node(T &&value);
    static std::unique_ptr<Node> get_new_node(const T &value);
    static std::unique_ptr<Node> get_new_node(T &&value);
};

template <typename data_t, typename weight_t>
struct HuffmanTreeNodeData {
    std::optional<data_t> data;   // 叶子存字符，内部节点为 nullopt
    weight_t weight;              // 该子树的权值和
};

template <typename data_t, typename weight_t>
using HuffmanTreeNode = Node<HuffmanTreeNodeData<data_t, weight_t>, 2>;
```

要点：

- `Node` 是通用 N 叉节点，`N` 默认 2 即二叉树。
- 用 `std::optional` 区分叶子（有字符）与内部节点（`nullopt`），不必额外存标志位；
  判定叶子只需要一句 `data.has_value()`。
- `weight` 对叶子是频率、对内部节点是两孩子权值之和，构造与 `huffman_wpl`
  都直接读它，不重复求和。

## 3. 函数签名

```cpp
template <typename data_t, typename weight_t>
std::unique_ptr<HuffmanTreeNode<data_t, weight_t>>
construct_huffman_tree(const std::vector<std::pair<data_t, weight_t>> &leaves);

template <typename data_t, typename weight_t>
std::map<data_t, std::string>
build_code_table(const HuffmanTreeNode<data_t, weight_t> *tree);

template <typename data_t, typename weight_t>
weight_t huffman_wpl(const std::map<data_t, std::string> &codes,
                     const std::vector<std::pair<data_t, weight_t>> &frequencies);
```

| 函数 | 语义 | 复杂度 |
| --- | --- | --- |
| `construct_huffman_tree` | 最小堆贪心：反复弹出权值最小的两棵子树，合并后压回，直到只剩一棵；`leaves` 为空返回 `nullptr` | O(n log n) |
| `build_code_table` | 自根 DFS 生成 `map<字符, 编码>`，向左记 `'0'`、向右记 `'1'`，叶子处记录完整路径；空树返回空表 | O(n log n)（含 map 插入） |
| `huffman_wpl` | 由编码表与频次计算 Σ(频次 × 码长)，即编码整段文本的比特数 | O(n log n) |

`build_code_table` 返回 `std::map` 而不是按 DFS 顺序的向量：map 按 `data_t`
升序排列，打印结果因此与遍历顺序、与堆的弹出顺序都无关。`huffman_wpl` 直接
吃这张表，不重复遍历树，保证「打印出来的编码」与「报告的 WPL」用的是同一份
数据。

### 3.1 确定性规则（样例逐行比对依赖它）

题面明确「不要求编码与参考实现完全一致，只要 WPL 相同」，但权值相同的节点在堆里
如何排序会改变树的具体形状，从而改变 0/1 模式。为了让同一份输入永远产出同一张
编码表，本实现给每个节点编号，按 `(weight 升序, id 升序)` 决定弹出次序：

- 第 `i` 个叶子的 `id = i`，与 `leaves` 的输入顺序一致（输入按
  `(次数升序, 字符升序)` 排好，见 §4）；
- 每新建一个内部节点，`id` 取递增计数器（从叶子数继续编号）。

`std::make_heap` / `push_heap` / `pop_heap` 建的是**大顶堆**：`comp(a, b) == true`
表示 a 排到 b 之后。要「小的先弹」，比较器必须反着写：

```cpp
// a 排在 b 后面，当且仅当 a 的 weight 更大，
// 或 weight 相同但 a 的 id 更大。
bool operator()(const Entry &a, const Entry &b) const {
    if (a.weight != b.weight) return a.weight > b.weight;
    return a.id > b.id;
}
```

合并次序同样确定：**先弹出的作左孩子（`children[0]`）、后弹出的作右孩子
（`children[1]`）**，DFS 中「左 0 右 1」的编码也随之固定。

- 字符位置直接打印字符本身（空格就原样打一个空格），不做转义，所以空格那一行

上面这段就是 `outputs/case01.txt` 的实际内容。`hello world` 共 11 个字符：
l=3、o=2，空格与 d/e/h/r/w 各 1。WPL 手算核对：

```text
l            3 × 2 = 6
o            2 × 3 = 6
e/h/r/w      4 × 1 × 3 = 12
空格/d       2 × 1 × 4 = 8
                        ---
                         32
```

Kraft 和 = 1×2⁻² + 5×2⁻³ + 2×2⁻⁴ = 0.25 + 0.625 + 0.125 = 1，恰为满二叉树。

### 4.3 题面示例的编码不是前缀码

题面示例同时出现了 `code 10` / `code 11` 和 `code 100` / `code 101`：`10` 既是
`100` 的前缀、也是 `101` 的前缀，**该编码集合不是前缀码**。

这比「与参考实现不一致」更严重——它不是另一种合法方案，而是**根本不可能存在**。
用 Kraft 不等式验证：六个频次为 1 的字符码长 3 位、两个高频字符（o 频次 2、
l 频次 3）码长 2 位，

```text
Σ 2^(-li) = 6×2^-3 + 2×2^-2 = 0.75 + 0.5 = 1.25 > 1
```

前缀码的 Kraft 和必须 ≤ 1，1.25 意味着这样的前缀码在数学上不存在。因此题面给出的
**28 bit（6×3 + 2×2 + 3×2）是不可达的**，它只是那组非法编码的加权总长。

按真实哈夫曼树（频次 `1,1,1,1,1,1,2,3`）合并：
`1+1=2`、`1+1=2`、`1+1=2`、`2+2=4`、`2+2=4`、`3+4=7`、`4+7=11`，
内部节点权值之和 `2+2+2+4+4+7+11 = 32`，**WPL = 32 bit**，最长码 4 位、最短 2 位。
本任务以 32 bit 为准，题面示例的编码与 WPL 都不能直接照抄。

### 4.4 单字符边界

字符集只有一个字符时贪心一次都不合并、根即叶子，路径为空。若取「码长 0」，原文
将写不出任何比特，与「压缩后可还原」矛盾。因此约定：

**单字符的编码记为 `"0"`（长度 1），WPL = 该字符频次。**

例：`a` 的 WPL = 1、`aaaaaa` 的 WPL = 6（都不是 0）。

## 5. 构造原理：贪心 + 最小堆

### 5.1 算法

1. 为每个 `(字符, 频次)` 建一个叶子节点，装进最小堆；
2. 当堆中多于一个节点时：
   - 弹出权值最小的两棵子树 `node1`、`node2`；
   - 新建内部节点，权值为两者之和，`node1` 作左孩子、`node2` 作右孩子；
   - 把新节点压回堆；
3. 堆中剩下的唯一节点就是根。

### 5.2 为什么每次合并两个最小权值能得到 WPL 最小的树

先说一个恒等式，它是后面所有推导的基础：

> **WPL = 所有内部节点权值之和。**

理由：每条从根到叶子的路径上，每经过一个内部节点，该叶子的权值就贡献一次；
把内部节点按「它覆盖了哪些叶子」累加，恰好每个叶子被计了「它到根的深度」次。

于是「让 WPL 最小」等价于「让所有合并产生的内部权值之和最小」。而每次合并的代价
就是「当时两棵子树权值之和」，所以这变成一个**合并代价最小化**问题：每步都挑当时
最小的两个，就是让每一步的代价尽可能小。

直观上：权值大的叶子应该离根近（路径短），权值小的叶子离根远。哈夫曼的做法是
先把最小的两个凑成一个整体，让它们成为最深的一对兄弟；合成后的整体权值变大，自然
在后续轮次中被「往里挪」。整个过程中没有哪一步是「先付出大代价」，所以总代价最小。

严格的证明见 §6（交换论证），它给出的是「贪心选择不丢最优解」而非仅仅「看起来合理」。

### 5.3 复杂度 O(n log n)

设字符种类数为 `n`（即叶子数）。

- **建堆**：`std::make_heap` 对 `n` 个元素原地建堆，O(n)。
- **合并次数**：每次合并让堆中元素减少 1，从 `n` 减到 1 需要 **n − 1 次**合并。
- **每次合并**：两次 `pop_heap` + 一次 `push_heap`，每个都是 O(log n)；
  创建内部节点与搬运 `unique_ptr` 是 O(1)。
- **总计**：O(n) + (n − 1) × O(log n) = **O(n log n)**。

编码阶段：DFS 每个节点访问一次，共 O(n) 次操作；每次到叶子做一次 `map` 插入，
O(log n)，因此编码表构建是 O(n log n)。WPL 计算遍历 `n` 个频次条目，每次一次
`map::find`，O(n log n)。

空间：n 个叶子 + (n − 1) 个内部节点 = 2n − 1 个节点，O(n)；堆里同时最多 n 项，
O(n)；编码表 O(n × 最长码长)。递归栈深度等于树高，最坏（极端偏斜）为 O(n)。

## 6. 两个性质：前缀码与最优性

### 6.1 为什么哈夫曼编码一定是前缀码

前缀码的定义：**没有任何一条编码是另一条编码的前缀**。它保证解码无歧义——从左到右
读比特，一旦读出某个完整的码字就确定了一个字符，不会出现「继续读下去可能是另一个字符」
的情况。

哈夫曼编码的前缀性质来自一个纯结构性的事实：

1. **只有叶子携带字符。** 内部节点的 `data` 是 `std::nullopt`，编码只在 DFS 走到
   叶子（`data.has_value()`）时才记录。
2. **叶子之间不存在祖先关系。** 树的任何一个节点最多只有一个父节点，所以两个不同的
   叶子不可能出现在同一条从根到叶的路径上。
3. 一条编码就是「从根到该叶子」的路径。若编码 A 是编码 B 的前缀，就意味着 A 对应的
   叶子在「根到 B 的叶子」这条路径上，即 A 的叶子是 B 的叶子的祖先——与第 2 条矛盾。

因此任意两条编码互不为前缀，解码只需一遍扫描，且唯一。

> 反例正是题面示例：`10` 对应某个叶子，而 `100` / `101` 又在以它结尾的路径上继续
> 延伸，等于让一个叶子成了另一个叶子的祖先——在二叉树里这不可能发生，所以那组编码
> 不可能由任何二叉树产生。

### 6.2 为什么它是最优的：交换论证

要证：在所有「每个字符都是叶子、没有字符在内部节点上」的二叉树中，哈夫曼树使 WPL 最小。

**引理（最深兄弟对）。** 设 `a`、`b` 是权值最小的两个叶子。则存在一棵最优树，其中
`a` 与 `b` 是兄弟，且深度最大。

*证明。* 取任意一棵最优树 T。

1. 最优树里没有「只有一个孩子」的内部节点：若 `u` 只有一个孩子 `v`，把 `u` 收缩掉
   （让 `v` 直接接替 `u` 的位置），`v` 子树里所有叶子的深度都减 1，WPL 严格下降，
   与最优性矛盾。所以每个内部节点都有两个孩子；取最深的一个叶子 `y`，它与父节点
   的另一个孩子是兄弟，而那个孩子也必然是叶子（否则沿它往下还有更深的叶子），
   记作 `z`，`y`、`z` 同处最大深度 `d_max`。
2. 把 `y` 与 `a` 交换、`z` 与 `b` 交换（只交换它们携带的字符与权值，不改变树的形状）。
   交换后 `a`、`b` 占据了最深的那对兄弟位置，而 `y`、`z` 去到了 `a`、`b` 原来的
   位置。
3. WPL 的变化：记 `d_max` 为最深深度，`d_a`、`d_b` 为交换前 `a`、`b` 的深度。
   由于 `a`、`b` 权值最小，`w_a ≤ w_y`、`w_b ≤ w_z`，且 `d_max ≥ d_a`、`d_max ≥ d_b`，
   交换后的增量为

   ```text
   Δ = (w_y − w_a)(d_a − d_max) + (w_z − w_b)(d_b − d_max) ≤ 0
   ```

   即 WPL 不增；T 已最优，故交换后仍是同样 WPL 的最优树，且 `a`、`b` 是最深兄弟对。

**归纳。** 由上一步，存在最优树 T' 让 `a`、`b` 成为最深的一对兄弟。把 `a`、`b`
合并成一个权值为 `w_a + w_b` 的新叶子，得到规模为 `n − 1` 的问题：

```text
WPL(T') = WPL(T'') + (w_a + w_b)
```

（最深的一对兄弟被合并后，二者各自贡献的 `w × d_max` 变成新叶子的
`(w_a + w_b) × (d_max − 1)`，差值恰为 `w_a + w_b`。）

哈夫曼算法的第一步做的正是这件事：合并 `a`、`b`。于是「原问题的某个最优解」
与「合并后子问题的最优解 + 一次合并代价」一一对应，子问题仍可递归用同样的论证。
归纳下去，贪心的每一步都不丢最优解，最终得到的树 WPL 最小。∎

| 等价校验：`Σ 频次 = 43`（句子长度） | 43 |

码长分布：3 位 1 个（空格）、4 位 2 个（o、e）、5 位 24 个。
Kraft 和 = 2⁻³ + 2×2⁻⁴ + 24×2⁻⁵ = 0.125 + 0.125 + 0.75 = **1**（满二叉树）。

### 7.2 与八位定长编码的压缩率

定长编码每字符 8 位（题面 ASCII 口径），哈夫曼编码为 Σ(频次 × 码长)。

| 样例 | 原文长度 | 定长 8 位 | 哈夫曼 WPL | 压缩率 |
| --- | --- | --- | --- | --- |
| case01 `hello world` | 11 | 88 | 32 | **36.4 %** |
| case04 `abcdefgh` | 8 | 64 | 24 | 37.5 % |
| case05 `aaaaaaaaab` | 10 | 80 | 10 | **12.5 %** |
| case07 pangram | 43 | 344 | 192 | **55.8 %** |
| case08 `Hello, World! Is this OK?` | 25 | 200 | 101 | **50.5 %** |

- **均匀分布**（case04）：8 个字符正好占满 3 位，压缩到 3/8 = 37.5 %，这是
  「字符种类数恰好是 2 的幂」时的极限，再压不下去。
- **极端偏斜**（case05）：一个字符占 9/10，编码几乎等于 1 位/字符，压缩到 12.5 %。
  这说明哈夫曼对偏斜分布收益最大。
- **自然语言**（case07）：空格频率最高（8/43 ≈ 19 %），排在码长 3 位；大量低频
  字符占 5 位，平均 192/43 ≈ 4.47 位/字符，压缩到 55.8 %。
- **标点与大小写**（case08）：字符种类多（18 种）而总量只有 25 个，光靠频率差压
  得有限，平均 101/25 = 4.04 位/字符，压缩到 50.5 %。
- **反例提醒**：若分布接近均匀且字符种类很多，哈夫曼并不比定长编码好多少——
  它的收益完全来自「频率差异」。

### 7.3 逐项核对结论

每个样例都核对了四条，全部通过：

1. **编码是前缀码**：任意两条编码互不为前缀（独立 Python 实现双向比对）；
2. **Σ(次数 × 码长) == WPL**：`huffman_wpl` 的返回值与独立重算一致；
3. **Kraft 不等式**：case01/case04/case05/case07/case08 的 Kraft 和恰为 1（满二叉树），
   case02/case03 为 0.5（单字符有一条未用分支），均 ≤ 1；
4. **单字符边界**：case02、case03 的编码是 `"0"`、长度 1，WPL = 频次而非 0。

另外：

- 用 `-fsanitize=address,undefined` 编译后跑全部样例，**0 泄漏、0 重复释放、
  0 未定义行为**；`unique_ptr` 的所有权在合并时用 `std::move` 转移。
- 空文件（0 字节）与空行（只有 `\n`）都输出 `EMPTY` / `WPL 0`，逐字节确认。
- 只有空格的行（`   `）会输出一条 `char   cnt 3` 加一条 `char   code 0` 与
  `WPL 3`，验证「字符位置原样打印、不转义」这条格式约定。
