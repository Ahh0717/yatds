# 森林与二叉树的转换（forest）

> 左孩子右兄弟表示法下，森林与二叉树一一对应。
> 森林的前序遍历等于对应二叉树的前序遍历，森林的后序遍历等于对应二叉树的中序遍历。

对应题面：`src/Tree/Baseline/forest/README.md`。

## 2. 左孩子右兄弟表示法的原理

### 2.1 表示规则

对一般树中的每个节点：

- 它的**第一个孩子**成为二叉树中的**左孩子**；
- 它的**其余孩子**依次成为前一个兄弟的**右孩子**，形成一条右兄弟链。

对森林：第一棵树的根成为二叉树的根；森林中其余各树的根，依次成为前一棵树根
的**右孩子**。

例子（题面示例森林，两棵树 A(B,C,D) 与 E(F,G)）：

```text
Forest:                       Binary tree (LCRS):
    A            E                  A
   /|\          / \                / \
  B C D        F   G              B   E
                                   \   \
                                    C   F
                                     \   \
                                      D   G
```

读懂这张图的两个要点：

- **横向**：A 的三个孩子 B、C、D 变成了 `A.left = B`，再沿 `B.right = C`、
  `C.right = D` 串成右兄弟链。所以二叉树里不存在「一个节点有四个孩子」——
  可变度数被压成了固定的两个指针。
- **纵向**：`A.right = E`。森林中第二棵树的根 E，并不在 A 的左子树里，而是
  直接挂在 A 的右指针上——这就是把「森林」当成「根节点彼此也是兄弟」来处理。

对应遍历结果：

```text
二叉树前序 = A B C D E F G   （= 森林前序）
二叉树中序 = B C D A F G E   （= 森林后序）
```

### 2.2 为什么任意森林都能一一映射成二叉树

构造过程是确定的、纯机械的，对每个节点只做三件事，没有分支选择：

1. 每个一般树节点**恰好**转成一个二叉树节点，数据原样复制；
2. 它的第一个孩子（若存在）唯一地成为它的左孩子；
3. 它其余的孩子各有唯一的「前一个兄弟」，唯一地挂成那条右链。

于是：

- **单射**：给定森林，每个节点在新树中的位置被完全确定（左孩子来自第一个孩子、
  右孩子来自下一个兄弟），所以两片不同的森林不可能转出同一棵二叉树——若两个
  节点在某棵树里的「父/兄弟关系」不同，转换后它们的 left/right 关系必然不同。
- **总函数**：任意有限的、有序的森林都满足上述规则，转换总能完成、不会卡住。
- **规模守恒**：节点数不变（一一对应），且二叉树中每个节点最多一个 left、
  一个 right，天然满足二叉树定义。

### 2.3 为什么可逆

逆过程同样机械，只需注意「right 指针的两种含义」：

| 二叉树的边 | 一般树中的含义 |
| --- | --- |
| `left` | 第一个孩子 |
| `right` | 下一个兄弟 |

因此还原时按**层级**拆开：

1. 从二叉树根出发沿 `right` 链走——链上每个节点都是森林中一棵树的根。这是因为
   森林把「各树的根」也当作兄弟串在同一条右链上。
2. 对其中每个节点，沿它的 `left` 出发的 `right` 链走——链上每个节点都是该节点的
   一个孩子。

两个方向互逆：转换时「第一个孩子→left、其余→right 链」，还原时正好「left→
第一个孩子、left 的 right 链→其余孩子」。二者的信息完全对称，没有任何信息在
转换中丢失或需要额外记录，所以是**双射**。测试里用「单向转换 → 还原 → 再转换
→ 再还原」的二次往返验证了这一点（结构完全一致，见 §5）。

## 3. 转换正确性：两条遍历对应关系

### 3.1 森林前序 = 二叉树前序

记 `F` 为森林，`T = forest_to_binary_tree(F)`。

**二叉树前序**的定义是：**根 → 左子树 → 右子树**。

在 LCRS 下：

- 二叉树的**根** = 森林第一棵树的根（或森林第一棵树的根链上的当前节点）；
- 二叉树的**左子树** = 该节点的**第一个孩子**及其整棵子树；
- 二叉树的**右子树** = 该节点的**下一个兄弟**（对树根而言是森林中下一棵树的根）。

**森林前序**的定义是：**先访问根 → 再依次访问每个孩子的子树**。

两者逐项对应：「根」相同；「左子树」就是第一个孩子的整棵子树（森林前序里紧接着
访问的那一块）；「右子树」就是后面那些兄弟（森林前序里在该孩子子树之后继续访问的
部分）。

**按节点归纳**：对某个节点 v，设左子树对应 v 的第一个孩子 c1、右子树对应 v 的
下一个兄弟。若递归假设「c1 的子树满足对应关系」，则 T 的前序 = v、c1 子树的前序、
v 兄弟子树的前序，而森林前序也恰好是 v、c1 子树、v 的其余兄弟——顺序与内容一致。
对森林的每棵树分别成立，逐棵拼接即得整个森林的结论。

一个容易看漏的点：森林的第二、三棵树在二叉树的**右子树**里，而不是「另一棵
独立的树」；正因为森林前序也是先走完第一棵再走第二棵，二者才对得上。

### 3.2 森林后序 = 二叉树中序

**二叉树中序**的定义是：**左子树 → 根 → 右子树**。

把 3.1 的对应关系代入：左子树 = 第一个孩子的整棵子树，根 = 当前节点，
右子树 = 后面那些兄弟。

**森林后序**的定义是：**先递归访问全部孩子的子树 → 最后访问根**。

于是：

- 中序先走「左子树」，对应森林后序里「先访问第一个孩子的整棵子树」；
- 中序再走「根」，对应森林后序里「所有孩子都访问完才访问当前根」；
- 中序最后走「右子树」，对应森林后序里「剩下的兄弟」。

注意这里和 3.1 的关键差别：**中序把根夹在左右子树之间，恰好对应后序把根放在
所有孩子之后**。如果换成二叉树前序，根在最前，对应的是森林前序而不是后序；
如果换成二叉树后序，根在最后，那么右子树（兄弟）会在根之后访问——这与森林后序
「先访问完本树所有孩子和根、再访问下一棵树」的次序不符。所以森林后序对应的
**只能是中序**，不能是二叉树后序。

「先访问完孩子再访问根」这一点在例子 case06 里最明显：树 `A(B(D,E),C(F(G,H),I))`
的森林后序是 `D E B G H F I C A`，A 排在自己整棵子树之后，紧接着才是下一棵树
`J(K)` 的部分 `K J`。

## 4. 实现要点

### 4.1 森林 → 二叉树

```text
tree_to_binary(node):
  创建 out(data = node.data)
  若 node 无孩子：返回 out
  out.left = tree_to_binary(node.children[0])   // 第一个孩子 → 左孩子
  tail = out.left
  for i = 1 .. node.children.size()-1:
      tail.right = tree_to_binary(node.children[i])  // 其余孩子 → 右兄弟链
      tail = tail.right
  返回 out
```

森林层再把这套结果串起来：

```text
forest_to_binary_tree(forest):
  若空：返回 nullptr
  root = tree_to_binary(forest[0])
  tail = root
  for i = 1 .. forest.size()-1:
      tail.right = tree_to_binary(forest[i])   // 后续树根 → 根的右链
      tail = tail.right
  返回 root
```

### 4.2 二叉树 → 森林

```text
binary_node_to_tree(node):
  创建 out(data = node.data)
  for child = node.left; child != nullptr; child = child.right:
      out.children.push_back(binary_node_to_tree(*child))
  返回 out            // 注意：本层只消费 left，兄弟链由循环接管

binary_tree_to_forest(root):
  for tree_root = root; tree_root != nullptr; tree_root = tree_root.right:
      forest.push_back(binary_node_to_tree(*tree_root))
```

**一个容易写错的地方**：`binary_node_to_tree` 内部递归时**不能再把 `child->right`
当作孩子传下去**，否则同一个兄弟会被创建两次（一次作为当前孩子的兄弟、一次作为
当前孩子的孩子）。所以递归只处理 `left` 链，`right` 由外层 `for` 循环统一消费。

### 4.3 遍历

前序 / 后序各是一行递归：前序先 `push` 自己再递归孩子，后序先递归孩子再
`push` 自己；森林层按顺序对每棵树调用，结果自然逐棵拼接。

### 4.4 输入解析

`tree_io.h` 把 stdin 全部切成 token：第一个 token 是棵数 k，之后依次读 k 个
token，每个 token 用递归下降解析括号表示法：

```text
node := label [ '(' node (',' node)* ')' ]
```

标签必须是单个可见 ASCII 字符（`0x21`–`0x7E`），且不能是 `,`、`(`、`)`。
解析器会校验括号闭合、逗号与右括号的位置、token 数量是否与 k 一致；任何不合法
输入都抛 `std::runtime_error`，由 demo 打印 `ERROR:` 到 stderr 并以 1 退出。

## 5. 测试用例设计

六个样例覆盖了森林结构的主要形态，期望输出全部由实现实跑生成，再逐行人工核对
三条不变式（核对方法和结果见 §5.2）。

| 样例 | 输入 | 覆盖点 |
| --- | --- | --- |
| case01 | `2` / `A(B,C,D)` / `E(F,G)` | 题面示例：多孩子 + 多树 |
| case02 | `1` / `A` | 单棵树单节点：最小非空森林 |
| case03 | `1` / `A(B(C(D)))` | 深链：每层只有一个孩子，右链为空 |
| case04 | `1` / `R(A,B,C,D,E)` | 宽兄弟：根有 5 个孩子，全在右兄弟链上 |
| case05 | `0` | 空森林：六组行照常输出，序列均为空，不留行尾空格 |
| case06 | `2` / `A(B(D,E),C(F(G,H),I))` / `J(K)` | 混合：多树 + 多孩子 + 不同深度 |

设计意图：

- **case03 与 case04 是一对**
  两者在转换后都是单链，但**成因不同**：
  - case03 `A(B(C(D)))` 每层只有一个孩子，右链全空，二叉树退化为
    `A.left=B.left=C.left=D`，测的是「只有 left 的链」；
  - case04 `R(A,B,C,D,E)` 每层也只有一个孩子，但 root 有 5 个孩子，
    二叉树退化为 `R.left=A`，再 `A.right=B.right=C.right=D.right=E`，
    测的是「只有 left 一次、随后全是 right 的链」。
  两者合起来覆盖「递归深度」与「兄弟链长度」两个维度，能暴露「忘了接兄弟链」
  或「兄弟链接错层」这类典型 bug。

- **case02 与 case05 是边界**
  case02 只有一个节点，验证「无孩子时 left/right 都为 null」不会崩；case05 是
  空森林，验证输出排版在「所有序列为空」时仍然逐字正确（尤其是**不能有行尾空格**）。

- **case06 是综合**
  两棵树结构不同（一棵三层、一棵两层）、其中一棵有多个孩子且深度不均，用于确认
  多棵树在根右链上的拼接与每棵树内部的兄弟链互不干扰。

### 5.1 往返验证

除了逐行比对输出，还单独做了结构级往返测试：

```text
森林 F  → 二叉树 B → 森林 F' → 二叉树 B' → 森林 F''
要求：F、F'、F'' 的括号表示法完全一致，且三次的森林遍历结果一致。
```

六个样例全部通过（含空森林）。二次往返通过说明转换不仅「能还原」，而且**幂等**，
不会每转一次就少一层或多一层。

### 5.2 三条不变式的核对方法

为了不「用被测程序的输出验证被测程序」，核对时**另写了一份独立的 Python 实现**
（只按 §2、§3 的定义重写，不复用 C++ 代码），对六个样例分别计算：

1. 森林前序 / 后序；
2. 按 LCRS 规则手工构造二叉树的形状，再算二叉树前序 / 中序。

结果是逐值比对 C++ 输出。

**核对结论（六个样例全部通过）：**

| 不变式 | case01 | case02 | case03 | case04 | case05 | case06 |
| --- | --- | --- | --- | --- | --- | --- |
| 森林前序 == 二叉树前序 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 森林后序 == 二叉树中序 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 往返后与原森林一致 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

关键样例的实际值（供人工复核）：

```text
case06  A(B(D,E),C(F(G,H),I)) + J(K)
  森林前序 = A B D E C F G H I J K
  森林后序 = D E B G H F I C A K J
  二叉树前序 = A B D E C F G H I J K   ← 与前序一致
  二叉树中序 = D E B G H F I C A K J   ← 与后序一致

case04  R(A,B,C,D,E)
  森林前序 = R A B C D E        森林后序 = A B C D E R
  二叉树前序 = R A B C D E      二叉树中序 = A B C D E R
```

## 6. 输出格式

固定三节、每节两组，共六组行：

```text
=== Original Forest ===
Forest preorder:  A B C D E F G
Forest postorder: B C D A F G E

=== Binary Tree (from forest) ===
Binary preorder:  A B C D E F G
Binary inorder:   B C D A F G E

=== Recovered Forest ===
Forest preorder:  A B C D E F G
Forest postorder: B C D A F G E
```

- 标签左对齐到第 18 列后接序列，元素之间一个空格；
- 某一组序列为空时，该行到冒号就结束，**不留行尾空格**（case05 即如此）；
- 节与节之间一个空行，全文末尾不再额外留空行；
- 输入非法时 stdout 不输出任何内容，`ERROR:` 只写到 stderr，退出码 1。

## 7. 复杂度

设森林（或等价地，转换后的二叉树）共有 `n` 个节点。

| 函数 | 时间 | 空间 |
| --- | --- | --- |
| `forest_to_binary_tree` | O(n) | O(n) 结果 + O(h) 递归栈 |
| `binary_tree_to_forest` | O(n) | O(n) 结果 + O(h) 递归栈 |
| `forest_preorder` | O(n) | O(h) 递归栈 + O(n) 结果 |
| `forest_postorder` | O(n) | O(h) 递归栈 + O(n) 结果 |

**都是 O(n)，理由相同**：每个节点在转换中恰好创建一个新节点、在遍历中恰好被
访问一次。没有任何嵌套的内层扫描——右兄弟链是用 `tail` 指针在 O(1) 内追加的，
不是每次重新从头找尾（若那样写，宽节点的树会退化成 O(n²)）。

递归栈深度 `h` 等于树高：case03 这类退化链 `h = n`，所以最坏空间是 O(n)。
这是递归实现固有的；若要求严格 O(1) 额外空间，需要用显式栈改写为迭代，
本任务不需要。

解析阶段的时间是 O(输入长度)，与节点总数同阶。
