# 任务 3：双链 DNA 目标蛋白编码片段检索

## 1. 问题与整体流程

给定 DNA 串 `S`（长度 N）与目标蛋白串 `P`（长度 m），要找出 `P` 在
**6 条蛋白序列**（正向链 3 个阅读框 + 反向互补链 3 个阅读框）中的全部出现，
把它们映射回原 DNA 的坐标，再回答 `q` 个"区间内有多少个匹配被完整包含"的查询。

```text
S ──┬── 正向链 S ──────────── 阅读框 1/2/3 ──→ 蛋白序列 1/2/3 ──┐
    │                                                          ├── KMP 找 P 的
    └── 反向互补链 RC(S) ────── 阅读框 1/2/3 ──→ 蛋白序列 4/5/6 ──┘   全部出现
                                                                    │
                                              坐标映射（蛋白下标 → DNA 区间）
                                                                    │
                                              排序 → 输出 → 前缀和查询
```

各阶段复杂度（N 为 DNA 长度，m 为 P 长度，K 为匹配数，q 为查询数）：

| 阶段 | 时间 | 空间 |
| --- | --- | --- |
| 反向互补 + 6 帧翻译 | O(N) | O(N) |
| `pi` 数组 | O(m) | O(m) |
| 6 条蛋白序列上跑 KMP | O(N + m)：6 条蛋白总长约 2N，每条扫一遍再加 pi 的 O(m) | O(m) |
| 坐标映射 + **计数排序** | O(N + K)：值域是 L ∈ 1..N，不需要比较排序的 log | O(N + K) |
| 前缀和预处理 | O(N + K) | O(N) |
| 每个查询 | O(1) | — |
| **合计** | **O(N + m + q)**（K ≤ 2N，其上界被 N 吸收） | **O(N + m)** |

这里有两个容易被忽略的点，正好决定了能不能真正做到 O(N + m + q)：

- **排序不是 O(K log K)**：所有匹配的 L 只有 1..N 这 N 个可能取值，用
  计数排序即可线性完成。见 4.5 与第 5 节。
- **K ≤ 2N**：6 条蛋白序列总长约 `2N/3 × 3 = 2N`，每条上每个位置最多命中
  一次，所以 K 至多 2N，`O(N + K) = O(N)`。于是总计里没有独立的 K 项。

## 2. 翻译：6 条蛋白序列

### 2.1 密码子表

用 64 项静态表，下标按 `A:0 C:1 G:2 T:3` 取 `b1*16 + b2*4 + b3`：

```cpp
const char kCodonTable[64] = {
    'K','N','K','N',  'T','T','T','T',  'R','S','R','S',  'I','I','M','I',  /* 首位 A */
    'Q','H','Q','H',  'P','P','P','P',  'R','R','R','R',  'L','L','L','L',  /* 首位 C */
    'E','D','E','D',  'A','A','A','A',  'G','G','G','G',  'V','V','V','V',  /* 首位 G */
    '*','Y','*','Y',  'S','S','S','S',  '*','C','W','C',  'L','F','L','F',  /* 首位 T */
};
```

表不是手敲的：先用 Python 从题面表格反推成 A/C/G/T 下标序，再逐项粘回源码，
两边对过一遍。`*`（终止密码子）就是普通字符，照常参与匹配。

### 2.2 阅读框

`readFrame(seq, f)` 从 **0-based 下标 f−1** 开始、每 3 个取一个密码子，
循环条件 `i + 2 < n` 保证末尾不足 3 个的碱基被丢弃。三帧的蛋白长度分别是
`⌊(N-f+1)/3⌋`，例如 N = 23 时三帧长度为 7/7/7；N = 2 时三帧全为空。

### 2.3 反向互补

`RC[i] = complement(S[N-1-i])`，即"先反转再互换 A↔T、C↔G"。实现里一步完成：
取 `S[N-1-i]` 再互补，避免真的建一个反转串。注意 `RC` 的**方向是 5'→3' 的反向链**，
这正是翻译所需要的方向。

## 3. 匹配：KMP 找出全部（可重叠）出现

任务之间不互相 include，所以 task3 独立实现一份 `computePi` / `findAllOccurrences`，
没有引用 task2。

关键在命中之后的一步：

```cpp
if (j == m) {
    starts.push_back(i - m + 1);
    j = pi[j - 1];        // 不是 j = 0
}
```

`j = pi[j-1]` 把 `j` 退到"最长真前后缀"，于是"上一个匹配的后缀"可以继续当
"下一个匹配的前缀"，重叠出现不会漏掉。以 `text = "AAAA"`、`P = "AA"` 为例，
`j = 0` 的写法只会找到起点 0 和 2，而正确结果是 0、1、2 三个。

`pi` 数组按题面要求单独输出在第 1 行，输出的是 **P 的** pi 数组（不是某条蛋白序列的）。

## 4. 坐标映射：公式怎么来的

这是整个任务最容易写错的部分，所以从"碱基下标"而不是"公式"出发推导。

### 4.1 正向链

阅读框 f 的第 j 个密码子，其起始碱基在 0-based 下标

```text
p = (f - 1) + 3j
```

因为从 `f-1` 起步、每 3 个一读。一条匹配占 m 个密码子，覆盖 0-based 闭区间
`[p, p + 3m - 1]`。换成 1-based 闭区间，两边各加 1：

```text
L = (f - 1) + 3j + 1
R = (f - 1) + 3j + 3m
```

**验算**：f=1、j=0、m=1 时 `L=1, R=3`，正是 DNA 的前三个碱基，正确。

### 4.2 反向互补链

RC 的第 k 个碱基（0-based）来自原串第 `N - 1 - k` 个碱基。阅读框 f 的第 j 个
密码子占 RC 下标 `[(f-1)+3j, (f-1)+3j+3m-1]`，把它映射回原串：

- RC 下标越小 ⇒ 原串下标越大。所以原串上区间是
  `[N-1-((f-1)+3j+3m-1), N-1-((f-1)+3j)]`
  = `[N-(f-1)-3j-3m, N-(f-1)-3j-1]`（0-based）；
- 加 1 转成 1-based：`[N-(f-1)-3j-3m+1, N-(f-1)-3j]`。

即

```text
L = N - (f - 1) - 3j - 3m + 1
R = N - (f - 1) - 3j
```

**验算**：取题面样例 `S = AATGGCTTTAAGCCATCATGGCC`（N = 23），
它的 RC 第 2 帧是 `AMMA*SH`，P = `MA` 命中在 j = 2（RC 下标 7..12 = `ATGGCT`）。
代入 f=2、j=2、m=2：

```text
L = 23 - 1 - 6 - 6 + 1 = 11
R = 23 - 1 - 6         = 16
```

对照题面样例输出，确实有 `11 16 - 2` 这一行。再回原串验证：
`S[11..16] = AGCCAT`，其反向互补是 `ATGGCT`，翻译得 `MA`。
**区间方向是对的**：RC 上位置靠前的密码子，在原串上对应靠后的一段。

这也说明为什么 R 的表达式里没有 `-3m`：RC 中**第 j 个**密码子的起点对应原串
的 **R** 端（它是原串区间的最后一个碱基），而区间另一端才要往左推 3m 个碱基。

### 4.3 用暴力逐碱基验证公式（不靠手算）

为了排除"公式看着对其实错一位"，我写了一个**不引用公式**的验证器：对每个
(frame, j, m) 组合，直接在 RC 上取出该密码子块的下标集合，逐一映射回原串，
得到 `min+1` 与 `max+1`，再与公式结果比较。覆盖 4 条 DNA × 3 帧 × 全部 (j, m)：

```text
反向公式：brute force 全部通过（4 条 DNA × 3 帧 × 全部 (j, m)）
正向公式：brute force 全部通过（3 条 DNA × 3 帧 × 全部 (j, m)）
```

这一步比手算可靠得多，也顺带确认了两点容易忽略的性质：

- **匹配长度恒为 3m**，与帧和链无关。所以 `R - L + 1 = 3m` 恒成立
  （反向公式里 `R - L + 1 = 3m` 也成立）；
- **同一条链上的不同匹配不会共享 L**（见 4.4），所以 L 相同只可能跨链发生。

### 4.4 排序规则与一个结构性结论

题面要求：L 升序；L 相同按 strand（`+` 在 `-` 前）；再相同按 frame 升序。

先说一个可以证明的事实：**同链内 L 唯一，但跨链会撞 L，所以二、三级键都必须有**。

- **同一条链内部，不同帧不可能共享 L**。设同链的 f₁、f₂ 在 j₁、j₂ 处 L 相同。
  正向 `L = (f-1) + 3j + 1` 给出 `f₁ - f₂ = 3(j₂ - j₁)`；左边绝对值 ≤ 2，
  右边是 3 的倍数，故两边都为 0，即 `f₁ = f₂`、`j₁ = j₂`，其实是同一个匹配。
  反向同理。所以同链内 L 唯一标识一个匹配；
- **但跨链可以同 L**：正、反两条链的 L 出自两套不同公式，没有 mod 3 的约束，
  撞上是完全可能的。`case11` 就是：S = `AAAATTT`、P = `KF`，
  正链 frame 2 在 j=0 产出 `L = 1 + 1 = 2`，反链 frame 1 在 j=0 产出
  `L = 7 - 0 - 6 - 6 + 1 = 2`。输出正是

  ```text
  2 7 + 2
  2 7 - 1
  ```

  **同 L、不同链、frame 也不同**，恰好把第二、三级排序键都用上了。

所以排序键 `(L, strand, frame)` 的三级都不可省。

另一个必然成立的性质：所有匹配长度都是 3m，**L 相同必然推出 R 也相同**——
即这些匹配占据**完全一样的 DNA 区间**，只能靠 `(strand, frame)` 区分。
`case03` 是更简单的一例：`S = CACGTG`（回文），P = `HV`，正反两条链都在
`[1,6]` 上编出 `HV`，输出 `1 6 + 1` / `1 6 - 1`。

### 4.5 排序为什么不用比较排序

上面的排序键看起来需要 `std::sort`，即 O(K log K)。但 **L 的值域固定是
1..N**，用**稳定计数排序**就够：

1. 统计每个 L 出现次数，做前缀和得到每个 L 的写入起点，O(N)；
2. 按生成顺序依次把匹配放进对应 L 的槽位，O(K)。

因为稳定，同一 L 内部保持生成顺序。而生成顺序被刻意安排成
**正链 frame 1,2,3 → 反链 frame 1,2,3**，这正是 `(strand, frame)` 要求的先后。
于是"稳定 + 生成顺序"直接给出题面要求的完整次序，不需要任何比较。

K ≤ 2N（6 条序列总长约 2N，每处最多命中一次），所以这一步是 O(N + K) = O(N)。

## 5. 区间计数：为什么能 O(1)

所有匹配长度都是 `3m`，即 `R = L + (3m - 1)`。于是

```text
匹配被 [l, r] 完整包含
  <=>  l <= L  且  L + (3m-1) <= r
  <=>  l <= L <= r - (3m - 1)
```

只需要在"L 坐标轴"上数点。做法：

1. 把 L 的值域 `1..N` 做成差分数组，出现一次就 +1，再求前缀和
   `prefix[x] = #(L <= x)`，预处理 O(N + K)；
2. 查询时 `hi = min(r - (3m-1), N)`，`lo = l - 1`，答案
   `= prefix[hi] - prefix[lo]`，O(1)。

代码里就是这几行：

```cpp
long long MatchCounter::countContained(long long left, long long right) const {
    if (span_ < 0) return 0;                 // P 为空
    const long long n = prefix_.size() - 1;
    if (right - span_ < left) return 0;      // r - 3m + 1 < l：区间装不下一个匹配
    long long hi = right - span_;            // = r - 3m + 1
    if (hi > n) hi = n;                      // 上界封顶到 N
    long long lo = left - 1;                 // prefix_[l-1] = #(L <= l-1)
    if (lo < 0) lo = 0;
    if (lo > n) lo = n;
    return prefix_[hi] - prefix_[lo];
}
```

各类边界分别对应：

| 情形 | 处理 |
| --- | --- |
| `r - 3m + 1 < l`（区间放不下一个完整匹配） | 直接返回 0 |
| `r - 3m + 1 > N`（上界越界，如 `r = N`） | 封顶到 N |
| `l = 1`（`l - 1 = 0`） | `prefix_[0] = 0`，自然成立 |
| `l = r` | 必然 `r - 3m + 1 < l`（m ≥ 1 时 3m ≥ 3），返回 0 |
| P 为空 | `span_ = -1`，一律返回 0 |

注意 `hi` 与 `lo` 都先封顶再相减，所以不会出现无符号/负下标。`prefix_` 用
`long long` 存，但 K ≤ 2N ≤ 2×10^6 级别，`int` 其实也放得下；这里只是留着余量。

### 7.2 随机差分

`tools/fuzz_task3.py`，7 类生成器轮转（`case_id % 7`）：

| 生成器 | 目的 |
| --- | --- |

"同一 L 多条记录"全部发生在正反链之间、同链一例也没有，这正好反过来验证了
4.4 的结论；"重叠"则验证了 KMP 命中后 `j = pi[j-1]` 的写法。

`tools/gen_large_task3.py`（`make large` 会自动调用）确定性地生成：

- **N = 1 000 000** 的随机 DNA；
- 在随机背景上**定点植入**已知匹配：正链槽位写入 P 的密码子编码，
  反链槽位写入其反向互补；取 `frame = s mod 3 + 1`（反链是相应的镜像式），
  保证植入点落在该帧的密码子边界上，坐标可直接算出；
- **q = 200 000** 个查询，四类轮转：围绕植入匹配（含 `R` 差 1、`L` 差 1 的
  近似区间）、短于 3m 的区间、全随机区间、`(1,N)`/`(1,1)`/`(N,N)` 等边界。

默认参数下植入 24 999 个匹配，另有极少数偶然匹配命中（本次为 0）。

**期望输出也是独立算的**：匹配用 `str.find`（CPython 的子串搜索），
区间答案用 `bisect` 在有序 L 上数点，并且再随机抽 300 条查询用**线性扫描
暴力**复核。生成器还会逐条断言"每个植入点都出现在期望匹配表里"。

### 8.2 实测数据

环境：Intel Xeon Platinum 8358P（共享云主机，`cpu MHz` 在 0.9–2.6 GHz 漂移），
`g++ 15.2.0 -O2`。每档跑 5–7 次取**最小值**（排除首次缺页与调度抖动）。

```text
大样例输出      : 0.99 MB，与独立期望逐字节一致

n=1000000, K=24999, q=0 (换 P 使 K=0)      21.8 ms
n=1000000, K=24999, q=0                    26.3 ms
n=1000000, K=24999, q=200000               71.1 ms

单条查询边际成本 ≈ 224 ns（200000 条合计 44.8 ms）
翻译 + 6 帧 KMP 的每碱基成本 ≈ 22 ns
```

几分钟之内的量级；即使把 K 顶到理论上限（`P = K`，S 全为 `A`，
K = 999 998）：

```text
P=K   : K=999998, 161 ms
P=KK  : K=999995, 162 ms
P=KKK : K=999992, 166 ms
```

**K 从 2.5 万涨到 100 万，耗时只从 71 ms 涨到 161 ms**——因为排序已改成
线性计数排序，K 的增长只是线性的搬运，没有 log 因子。

### 8.3 线性验证

固定 q = 2e5，把 N 依次加倍：

```text
         N         K         q=0    q=200000
    125000      3124      4.7 ms     49.0 ms
    250000      6249      6.9 ms     51.1 ms
    500000     12499     14.2 ms     60.0 ms
   1000000     24999     26.8 ms     69.2 ms
```

`q=0` 一列随 N 近似翻倍（4.7 → 6.9 → 14.2 → 26.8），符合 O(N)。
`q=2e5` 一列几乎是平的（49 → 69）：N 变大时只有常数倍的增长，
增量几乎全部来自查询本身。

查询数扫描（N = 1e6，K = 24999 固定）：

```text
q=0      :  36 ms
q=50000  :  44 ms
q=100000 :  57 ms
q=200000 :  78 ms
q=400000 : 124 ms
```

每多 10 万条查询约 +21 ms，即**单条约 210 ns**，且没有随 q 增长的趋势——
说明每次查询确实是 O(1)，而不是均摊了别的开销。

### 8.4 复杂度推导（O(N + m + q) 的来源）

```text
翻译            6 条序列，总长 ≈ 2N（每条 ≈ N/3 个密码子）      → Θ(N)
KMP             pi = Θ(m)；6 条序列各扫一遍 = Θ(2N + 6m)          → Θ(N + m)
坐标映射        每个命中 O(1)，共 K 次；K ≤ 2N                     → Θ(N)
稳定计数排序    统计 O(N) + 回填 O(K)                              → Θ(N + K) = Θ(N)
前缀和          填充 O(N) + 累加 O(N)                              → Θ(N)
每个查询        hi/lo 两次下标计算 + 两次数组读                    → Θ(1)
--------------------------------------------------------------
合计                                                               → Θ(N + m + q)
```

关键的两处"消掉 log"：

1. **排序**：L 的值域是 1..N，计数排序 O(N+K)，不是 O(K log K)；
2. **计数**：把"区间包含"化归为"L 落在一个区间内"，前缀和把每次查询
   从 O(K) 降到 O(1)。

另外 K ≤ 2N 这个上界也不是随手写的：6 条蛋白序列的总长度是
`3 × ⌊N/3⌋ + 3 × ⌊N/3⌋ ≈ 2N`，每条序列上一个位置最多贡献一个匹配，
所以 K 最多 2N。于是 O(N + K) 就等于 O(N)。

**空间**：6 条蛋白序列 O(N)，`pi` O(m)，匹配表 O(K) = O(N)，
前缀和 `long long[N+1]` = 8 MB（N = 1e6 时）。实测峰值 RSS **29.3 MB**
（N = 1e6、K = 24999 的大样例）。
